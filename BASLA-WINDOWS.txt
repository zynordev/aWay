aWay — Windows'ta derle & çalıştır (özet)
==========================================

Ayrıntılı rehber: client/BUILD-WINDOWS.md
Sinyal sunucusu CANLI: wss://away.bilgicoderteam.tr/ws  (istemcinin varsayılanı budur;
--server yazmana gerek yok). Yerel sunucu gerekmez.

1) Gereksinimler (bir kez):
   - Rust (MSVC):            https://rustup.rs   (varsayılan stable-x86_64-pc-windows-msvc)
   - Visual Studio Build Tools -> "Desktop development with C++"
   - H264 için: nasm kur (choco install nasm)  YA DA  derlemeden önce:  $env:OPENH264_NO_ASM=1

2) Derle (PowerShell, bu klasörün içinde):
   cargo build -p away-client --features media --release

3) Çalıştır — tek pencere GUI (flag yok):
   .\target\release\away-client.exe
   Açılan pencerede kullanıcı adı + şifre ile giriş yap.
   Hesabın yoksa giriş ekranındaki "Hesap oluştur" -> kullanıcı adı + şifre (2 kez)
   -> "Hesabı oluştur"; hesap açılınca otomatik giriş yapılır.
   Ana ekranda karşının adını yazıp "Bağlan"; sana bağlanınca "Kabul/Ret" çıkar.

   Uzak ekranı izlerken FARE + KLAVYE de çalışır (M4). Üstteki "Kontrol" kutusu açıkken
   pencerede yaptığın her şey karşıya gider. Kapatırsan sadece izlersin.
   - İmleç: kendi imlecin uzaktakinin bulunduğu yeri gösterir (yakalama uzak imleci
     çizmiyor; karşı taraf fareyi oynatırsa sen göremezsin — bu normal, M6'da eklenecek).
   - Türkçe harfler (ğ, ı, ş, ç…) doğru gider: düzeni SENİN makinen çözüyor.
   - Ctrl+Alt+Del gitmez (Windows bunu hiçbir uygulamaya iletmez, AnyDesk de ayrı yolla yapar).

   Hazır hesaplar (canlı sunucuda): halil / 123 , erdem / 456 , test / test1234 , test2 / test1234
   İki pencere aç:
     .\target\release\away-client.exe --user test  --pass test1234
     .\target\release\away-client.exe --user test2 --pass test1234 --connect test
   -> test penceresinde "Kabul et" -> test2 test'in ekranını görür.

4) Kalite / gecikme ayarları:
   Video tamamen yazılımsal kodlanıyor; maliyet piksel sayısı x fps ile orantılı.
   ÇÖZÜNÜRLÜK ARTIK OTOMATİK: tam çözünürlükte başlar, makine yetişemezse bir basamak
   iner (1920 -> 1536 -> 1228 -> 982 -> 784 -> 640), rahatladıkça geri çıkar.
   Değişimler konsola yazılır:  çözünürlük 1920x1080 -> 1536x864
   --fps SADECE KARE HIZI DEĞİL, GECİKME/KALİTE KOLUNUN KENDİSİ. Otomatik çözünürlük
   kare başına bütçeyi 1000/fps ms olarak alır (varsayılan 20 -> 50 ms):
     .\away-client.exe --fps 30        # DAHA AZ GECIKME, biraz daha yumusak goruntu
     .\away-client.exe --fps 12        # DAHA KESKIN goruntu, biraz daha fazla gecikme
     .\away-client.exe --scale 1       # tam çözünürlükte SABİTLE (koruma kapanır)
     .\away-client.exe --bitrate 8000  # bloklu görünüyorsa (yükleme elveriyorsa)
     .\away-client.exe --bitrate 1500  # yükleme dar / kareler geç geliyorsa

   ÖLÇÜM — tahmin etme, iki sayıya bak:
   - Ekranı PAYLAŞAN makinenin konsolunda açılışta bir kez:
       encode 8 çekirdekte (çok dilimli)      <- burada 1 yazıyorsa haber ver
     ve 5 sn'de bir şu satır:
       ekran 1228x690 | gönderilen 14.8 fps | atlanan 61 | dönüşüm 8.2 ms |
       encode 41.3 ms | 1900 kbps
     "dönüşüm + encode" toplamı 15 fps'te 66 ms'yi aşıyorsa darboğaz CPU'dur —
     otomatik mod bunu kendisi görüp iner. Aşmıyor ama fps yine düşükse gecikme
     ağdandır -> --bitrate düşür.
   - İZLEYEN tarafta uzak ekranın üst şeridinde "14 fps · 960x540" yazar. Bu sayı
     host'un "gönderilen" fps'inden belirgin düşükse sorun ağ/bant genişliğidir.
   Sorun devam ederse bu iki satırı Claude'a yapıştır.

Not: --features media OLMADAN derlersen GUI değil, geliştirici data-channel testi çalışır.
